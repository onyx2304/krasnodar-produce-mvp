# Зелёная корзина — MVP доставки фруктов и овощей

Мобильный веб-каталог с корзиной, демонстрационной формой оформления заказа, схемой Supabase/PostgreSQL и защищённой Netlify Function для будущей интеграции с Telegram.

## Важно: по умолчанию реальные заказы отключены

- Форма на сайте работает только как демо и **не отправляет данные**.
- Серверный обработчик `/.netlify/functions/create-order` возвращает `503`, пока `ENABLE_ORDERS` не установлена в `true`.
- Все цены в каталоге предварительные. Это не оферта и не подтверждённый прайс поставщика.
- Не вводите реальные персональные данные до настройки сервиса, политики обработки данных и юридических документов.

## Исправление каталога в браузере

`app.js` использует ES-модульный импорт из `products.js`, поэтому подключение в `index.html` должно иметь `type="module"`. Не удаляйте этот атрибут: без него браузер не выполнит скрипт, и каталог, поиск, фильтры и корзина не запустятся.

## Локальный просмотр сайта

Требуется Node.js 20+.

```bash
npm install
npm run dev
```

Netlify CLI покажет локальный адрес. Без настроенных секретов реальные заказы отключены. Для простого просмотра статической страницы можно также запустить любой локальный статический сервер, поддерживающий ES-модули.

## Настройка GitHub

1. Создайте приватный репозиторий GitHub.
2. Распакуйте архив и загрузите файлы в корень репозитория.
3. Убедитесь, что `.env` и реальные ключи не попали в Git. В репозитории должен быть только `.env.example`.
4. Подключите репозиторий к Netlify и оставьте команду сборки пустой; каталог публикации — `.`. Функции находятся в `netlify/functions`.
5. Сначала опубликуйте демо-сайт без секретов.

## Настройка Supabase

1. Создайте проект Supabase.
2. Откройте SQL Editor и выполните `supabase/schema.sql`.
3. В таблице `products` замените предварительные цены на цены, подтверждённые поставщиками.
4. Сохраните URL проекта и service-role key для серверной конфигурации Netlify. Service-role key обходит RLS, поэтому никогда не помещайте его в браузер, GitHub или переписку.
5. Таблицы заказов не имеют публичных политик чтения/записи. Доступ к ним в MVP идёт только из серверной функции.

## Настройка Telegram

1. Создайте бота через официальный `@BotFather`.
2. Напишите своему боту сообщение и получите `chat_id` допустимым для вас способом.
3. Добавьте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в Netlify → Site configuration → Environment variables.
4. Добавьте `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` туда же.
5. Оставьте `ENABLE_ORDERS=false`, пока не проверены тестовая база, цены, уведомления, доступы и документы.

## Контракт серверного обработчика

`POST /.netlify/functions/create-order`

Пример тела запроса:

```json
{
  "name": "Тестовый покупатель",
  "phone": "+7 900 000-00-00",
  "address": "ТЕСТОВЫЙ адрес, не реальный",
  "note": "Тестовая заявка",
  "items": [
    {"productId": "apple", "quantity": 2},
    {"productId": "greens", "quantity": 1}
  ]
}
```

Функция:
- выключена, если `ENABLE_ORDERS` не равно `true`;
- проверяет поля и количество товаров;
- берёт цены только из базы, а не доверяет ценам из браузера;
- требует сумму товаров от 1 000 ₽;
- сохраняет заказ и позиции в базе;
- после сохранения отправляет уведомление в Telegram;
- не возвращает клиенту внутренние ошибки базы.

`quantity` для килограммовых товаров поддерживает дробное значение, но текущий интерфейс корзины добавляет целые единицы. Это можно расширить после проверки правил взвешивания.

## Важные ограничения до запуска

- В текущей версии сайт намеренно не отправляет форму на сервер. Это сделано, чтобы не принимать реальные заказы случайно. После настройки инфраструктуры нужно отдельно подключить форму к `create-order` и протестировать её на тестовом проекте.
- Перед включением `ENABLE_ORDERS` реализуйте/проверьте ограничение частоты запросов, защиту от спама, обработку персональных данных и права администратора.
- Telegram-сообщение содержит телефон и адрес. Ограничьте доступ к чату с заказами.
- Сейчас стоимость доставки не рассчитывается автоматически: её нужно подтвердить до принятия заказа. Обработчик не должен подтверждать доставку автоматически.
- Цена, остаток и наличие должны быть проверены перед каждым заказом. Для развесных товаров согласуйте итоговую стоимость с покупателем.
- Прежде чем принимать оплату, добавьте подходящий законный способ расчётов, кассовые чеки и необходимые документы продавца.
- Для производственного запуска добавьте журнал событий, повторную отправку уведомлений, защиту от повторных заявок, согласие на обработку данных, политику конфиденциальности и юридическую проверку условий дистанционной торговли.

## Почему цены в базе хранятся в копейках

В `products.price_minor` 10900 означает 109,00 ₽. Целые числа исключают ошибки двоичной арифметики при денежных расчётах. В интерфейсе для простоты цены показываются округлёнными до рубля; для рабочего запуска нужно отображать копейки, если они используются.

- [ ] Секреты добавлены только в настройки серверного окружения.
- [ ] Протестированы ошибки базы и недоступность Telegram.
- [ ] Проверены согласие на обработку данных и политика конфиденциальности.
- [ ] Настроены защита от спама и ограничение частоты запросов.
- [ ] Проверены тариф доставки, минимальная сумма и подтверждение итоговой стоимости.
- [ ] Только после всего перечисленного включается `ENABLE_ORDERS=true`.
